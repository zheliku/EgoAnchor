# 单文件 TOML 参数管理实施计划

## 用户偏好

用户认可将运行参数从大量 argparse 迁移到 TOML，但不希望有太多 TOML 文件，也担心很多 config dataclass 让代码看起来复杂。

本计划采用：

- 单一运行配置文件：`Foundationpose_for_VR/config/runtime.toml`
- Python 内部不用大量 dataclass，使用 `SimpleNamespace` 点访问
- argparse 只保留入口级参数：`--config`、`--print_config`
- 不做多文件 preset，不做 Hydra/OmegaConf，不做复杂继承

## 目标形态

日常运行：

```powershell
pixi run python .\src\pose_server.py
```

默认读取：

```text
Foundationpose_for_VR/config/runtime.toml
```

如需指定另一份临时配置，可选：

```powershell
pixi run python .\src\pose_server.py --config .\config\runtime.toml
```

打印最终配置：

```powershell
pixi run python .\src\pose_server.py --print_config
```

## 为什么用一个 TOML 文件

优点：

- 配置入口唯一，不需要在多个文件之间找参数。
- 默认值与实际运行值都在同一个文件中，便于实验记录。
- 用户切换 SAM3/YOLOE 或 debug/realtime 只需改少数字段。
- 不需要 preset 继承、深度覆盖、多文件 merge 的心智负担。

代价：

- `runtime.toml` 会比较长。
- 但可以通过清晰 section、注释和字段命名解决可读性问题。

## 推荐文件命名

使用：

```text
Foundationpose_for_VR/config/runtime.toml
```

不建议叫：

- `default.toml`：容易误解为“默认但不一定运行”。
- `quest_sam3_realtime.toml`：太具体，后续换 YOLOE 或 debug 要改名字。
- `config.toml`：过泛，和项目其他配置容易混淆。

`runtime.toml` 表意最明确：这是当前运行参数。

## Python config loader 设计

新增：

```text
Foundationpose_for_VR/src/config/runtime_config.py
```

职责：

1. 读取 TOML。
2. 校验未知字段。
3. 将 dict 转成 `SimpleNamespace`，支持点访问。
4. 解析路径字段为 `Path`。
5. 提供 `print_effective_config()`。

示意：

```python
from types import SimpleNamespace


def to_namespace(value):
    if isinstance(value, dict):
        return SimpleNamespace(**{k: to_namespace(v) for k, v in value.items()})
    if isinstance(value, list):
        return [to_namespace(x) for x in value]
    return value
```

字段访问示例：

```python
cfg.segmenter.type
cfg.segmenter.prompt
cfg.sam3.async_enabled
cfg.ffs.use_trt
cfg.foundationpose.mesh_path
```

## 是否使用 dataclass

本计划不使用大量 dataclass。

原因：

- 当前主要目标是简化管理，不是构建复杂配置框架。
- 大量 dataclass 会引入很多样板代码。
- `SimpleNamespace + schema 校验` 足够满足当前需求。

仅保留一个轻量 schema 字典用于检查拼写错误：

```python
CONFIG_SCHEMA = {
    "server": {"run_stage", "local_debug", "send_when_no_pose", ...},
    "segmenter": {"type", "prompt", "max_det", "mask_threshold"},
    "sam3": {"checkpoint_path", "confidence_threshold", ...},
}
```

如果 TOML 写错：

```toml
[sam3]
intervel_sec = 1.0
```

启动时报：

```text
Unknown config key: sam3.intervel_sec
```

## argparse 保留范围

`pose_server.py` 只保留：

```text
--config
--print_config
```

可选：

```text
--dump_default_config
```

不再保留 `--sam3_*`、`--ffs_*`、`--cutie_*`、`--pose_*` 等运行参数。

`quest_pipeline.py` 可提供脚本入口，但也只读取同一份 `runtime.toml`。

## 代码迁移策略

### 1. 新增配置文件

新增：

```text
Foundationpose_for_VR/config/runtime.toml
```

内容覆盖当前 `build_arg_parser()` 的默认值。

### 2. 新增 config loader

新增：

```text
Foundationpose_for_VR/src/config/runtime_config.py
```

包含：

- `load_runtime_config(config_path: Path | None) -> SimpleNamespace`
- `validate_unknown_keys(data: dict) -> None`
- `resolve_paths(cfg, project_dir) -> None`
- `namespace_to_dict(cfg) -> dict`
- `print_effective_config(cfg) -> None`

### 3. 改造 `quest_pipeline.py`

当前：

```python
build_quest_pipeline(args: argparse.Namespace)
```

目标：

```python
build_quest_pipeline(cfg: SimpleNamespace)
```

典型替换：

```python
args.listen_port -> cfg.network.listen_port
args.seg_prompt -> cfg.segmenter.prompt
args.sam3_async -> cfg.sam3.async_enabled
args.ffs_use_trt -> cfg.ffs.use_trt
args.mesh_path -> cfg.foundationpose.mesh_path
```

### 4. 改造 `pose_server.py`

当前复用 pipeline parser。

目标：

- 只解析 `--config` / `--print_config`。
- 加载 `cfg`。
- `build_quest_pipeline(cfg)`。
- server 自己的发布/debug 参数也从 `cfg.server` 读取。

### 5. 保持测试

更新/新增测试：

- `src/test/test_runtime_config.py`
  - 能读取 `config/runtime.toml`
  - 路径字段解析正确
  - 未知字段会报错
  - 必要 section 存在
- 现有协议测试保持不变。

验证命令：

```powershell
pixi run python -m compileall src/config src/pipeline/quest_pipeline.py src/pose_server.py
pixi run python -m unittest src.test.test_runtime_config src.test.test_protocol_contract src.test.test_sam3_masker
```

## 命名和可读性建议

为了让单文件不头大：

1. section 顺序按运行链路排列：server -> network -> calibration -> segmenter -> depth/pose -> debug。
2. 每个 section 不超过 15-20 行，过长则拆子 section，例如 `[ffs.trt]`。
3. 在 TOML 顶部保留 5 行以内说明，不写大段文档。
4. 对最常改字段加短注释：`segmenter.type`、`segmenter.prompt`、`server.run_stage`、`debug.local_debug`。
5. 不在 TOML 里保留多套注释掉的配置块，避免文件变乱。

## 结论

推荐实现：

- 一个 `config/runtime.toml`
- `SimpleNamespace` 点访问
- 轻量 schema 校验
- argparse 只保留 `--config` / `--print_config`
- 不使用大量 dataclass
- 不使用多 TOML preset

这能最大化减少参数管理复杂度，同时保持代码和配置都直观。
