# EgoAnchor 论文设计规划

本文件是 `egoanchor_cn_final_v1.tex` 的写作路线，只记录当前定位、核心设计边界与冻结口径。逐轮评审日志不写入本文件；口径变化时直接改原条目。硬约束（术语、数字、代码事实）以仓库根 `AGENTS.md` 为准，本文件不重复其细则。

## 1. 论文定位

EgoAnchor 是一篇 **VR/MR 系统论文**。核心研究问题：

> 如何把异步、低频且质量波动的零样本物体位姿观测，转化为混合现实应用可持续消费的稳定动态对象锚点？

论文不以「pose-to-anchor contract」或接口形式化为理论中心，也不把单个滤波器、门限或通信组件包装为独立贡献。系统贡献来自两层架构及其协同设计：

1. **感知后端**：持续生成带对象身份、米制尺度、采集时刻与可靠性的相机系位姿观测；
2. **锚定运行时**：校正异步观测的时空语义，并按运动状态与有效性规则合成逐渲染帧对象锚点。

定位为系统论文，但方法部分按学术标准写：凝练核心思想、学术化表达，不逐一介绍工程实现。

## 2. 三项核心技术设计

用户口径：核心创新技术为**流水线设计**、**VCD 评分**、**运行时的观测校正与锚点合成**。论文中不表述为「前端和后端的实现」——「实现」降低贡献层级，「前端/后端」与物理部署位置混淆。统一表述为**感知后端的系统设计**与**锚定运行时的系统设计**。

### 2.1 面向锚定的感知流水线

流水线的目标不是单帧识别，也不是单独提高位姿估计精度，而是生成锚定运行时可持续消费的**完整观测**。四个阶段：语义初始化 → 时序分割 → 立体几何重建 → 零样本位姿估计，分别负责目标指定、身份保持、尺度恢复与位姿更新，共同产出观测元组 $o_f = (f, t_f, T_{o,f}^{c}, R_f)$（`eq:observation`；**上标只记坐标系、下标后缀记离散序号**，不写 $T_o^{c_f}$）。

区别于一般「检测—分割—位姿估计」流水线之处在于其输出同时具备：连续对象身份、米制几何、零样本 6DoF 位姿、采集时刻、帧标识、可靠性评分。因此小节标题保留「面向锚定」，不缩成「感知流水线」。

**证据边界**：四阶段未做逐项消融。措辞只能用「设计并实现」「组织为」「生成满足锚定需求的观测」，不得写「提出了优于现有方法的感知流水线」或「证明了四阶段设计的最优性」。其证据是完整系统可运行、日常物体覆盖与候选输出性能。

### 2.2 逐观测 VCD 评分

VCD（Visibility-gated Color-Depth）为每个位姿候选计算显式可靠性，综合投影可视度、颜色一致性、绝对深度一致性、结构深度一致性与模态可用性退化。

**术语裁定：不以「即时」作为相对既有视觉方法的差异点。** MegaPose 在推理中用粗分类器为渲染假设打分，FoundationPose 含对精化候选评分并择优的 pose-selection 模块；「此前的视觉评分都是离线的」在事实上不成立，审稿人会直接反驳。固定用**逐观测**：准确指出它为每一个最终位姿候选产生一个被运行时消费的显式可靠性。

VCD 与位姿估计器内部评分的真正区别在**系统角色**，而非是否在线：

| | 内部候选评分 | VCD |
| --- | --- | --- |
| 作用对象 | estimator 内部假设 | 最终输出候选 |
| 用途 | 假设选择 | 轨迹准入、失效判定、重获取期间抑制有害更新 |
| 可见性 | estimator 内部 | 显式暴露给运行时 |
| 退化 | —— | 按模态可用性退化 |

VCD 的三个语义层次不得混淆：方法输出 $[0,1]$ 连续评分；运行时以冻结阈值执行 admission；离线按分数诱导候选顺序，用 risk-coverage/AURC 检验风险判别性。VCD 本身不是排序算法，也不是位姿正确概率。

### 2.3 观测校正与准入

回答：一个异步到达的位姿候选，在时间、坐标与质量上能否进入锚点状态？

1. **采集时刻对齐**：按帧标识检索采集时刻的相机世界位姿，把相机系候选恢复为时间语义正确的世界系观测；
2. **质量与时序准入**：依 VCD 评分与采集时刻单调性决定候选是否写入时间索引轨迹；
3. **状态更新**：接纳观测更新运动状态估计、追加轨迹控制点、刷新静止锚定所需证据。

「观测校正」不表示重新优化候选位姿本身，而表示恢复其正确时空语义并完成风险准入。因此小节名必须带「与准入」，单写「观测校正」会被读成重新求解位姿。

### 2.4 状态感知的锚点合成

回答：在低频观测之间，以及静止、运动、遮挡与恢复期间，应用每个渲染帧应获得什么锚点？

1. 按近期控制点年龄确定历史查询时刻，不对尚未观测的当前状态外推；
2. 在已到达控制点之间做位置线性插值与旋转 SLERP；
3. 按估计运动状态在 Tracking 与 Locked 输出之间切换；
4. 静止锚定（StaticLock）抑制静止期残余波动，并由持续残差、累计漂移、明确运动与可靠性下降四类证据释放；
5. 有效性标注为输出附加可用性与可信状态，管理短时中断、保持、丢失与重获取。

核心特点是**不对所有状态使用同一套固定滤波参数**，而是按运动与可用性状态改变输出策略。这也是 StaticLock 有效的原因：静止期波动主要是噪声，运动期变化主要是真实运动，遮挡期观测不足应保持并显式退化，恢复期须重新准入后再更新。StaticLock 概念上属锚点合成，因机制篇幅长而保留独立子节，作用域收窄为 $\mathsf{Locked}$ 分支。

**StaticLock 的三个量不可互换**（据代码核定）：

- **原始接纳观测 $T_{o,j}^{w}$** —— 死区残差（`StaticLockController.cs:606`）、CUSUM 累积（`:619`）与 creep 插值目标（`:646`）的输入都是 `OnObservation` 传入的原始世界系位姿（调用方 `AnchorPolicyHost.cs:362` 传 `observation.WorldPose`）。
- **平滑控制点 $\widehat{T}_{o,j}^{w}$** —— 只进轨迹 $B_j$ 与 `eq:delayed-interp`，不参与 StaticLock 判据。
- **观测共识**（`obsConsensus`，不受死区约束的低通 EMA）—— 只服务「累计漂移」一类证据；其入锁瞬时值冻结为**锚定参考** $T_{o,\mathrm{ref}}^w$（`anchorOrigin`，`:174`/`:598`）。

**这一分工是论点而非细节**：证据取观测本身，才不会被平滑把真实偏移提前衰减——该理由只写在「进入」段（「取观测差分而非滤波器状态」），**不在「保持」段重复论证**。

StaticLock 三段（进入 / 保持 / 释放）各自的门槛符号必须在正文有词义，不能只出现在公式里。$R_{\mathrm{lock}}$ 的词义**嵌进「进入」段既有句子**（用附录参数表的中文名「入锁可靠性门槛」），不另起一句 gloss——用户要求「不要显得牵强，表述流畅连贯就行」。

有效性状态的**代码事实**为 **Tracking / Coasting / FrozenUncertain / Lost**（`AnchorStateMachine.cs`：gap ≤ 0.45~s → Coasting，0.45--1.0~s → FrozenUncertain，≥ 1.0~s → Lost）；旧规划中的「Buffered / Uncertain」不是代码状态名，不得回填。**但正文只写 `FrozenUncertain` 与 `Lost` 两名**：`约束.md` 第 3 条要求弱化占比，且 `\texttt{Tracking}` 与输出模式记号撞车。四个状态名齐写只保留在本文档与附录参数表的语义中。

## 3. 贡献结构（三条，已定稿）

三条：**EgoAnchor 系统 / 感知后端与锚定运行时 / 系统评价**（见 `egoanchor_cn_final_v1.tex` §1 的 `enumerate`）。**不要以「与 §3 一一对应」为由拆成四条**：曾拆开又回退，因为拆后两条各自过长、且与条目 1 的系统声明大面积重叠，压缩篇幅时首先牺牲的就是这两条的可读性。

1. **EgoAnchor 系统**：一套面向透视混合现实的零样本动态真实物体锚定系统，把异步、低频且质量波动的相机系位姿观测转化为稳定、世界一致且可恢复的世界系对象锚点。
2. **感知后端与锚定运行时**：感知后端把独立视觉基础模型组织为面向锚定的持续感知流水线，并以逐观测 VCD 评分量化候选与当前图像证据的一致性，**为观测失效判定与遮挡后的重新获取提供依据**（该因果 claim 是 VCD 值得单列的理由，改写时不得只写「输出可靠性评分」）；锚定运行时通过采集时刻对齐与质量准入校正异步观测，再以时间索引轨迹取值与静止锚定合成逐渲染帧对象锚点。
3. **系统评价**：具有平台参考的受控基准、同候选流组件消融与 24 名参与者的日常物体被试内研究，量化系统性能、关键机制、响应代价及其感知效用。

系统条目与技术条目存在包含关系是正常的：系统论文先声明完整能力，再展开最重要的系统设计。

**算子记号一级制**：**所有算子一律 `\operatorname{}` 直立体语义名**——$\operatorname{Detect}$/$\operatorname{Seg}$/$\operatorname{Stereo}$/$\operatorname{Reg}$/$\operatorname{Track}$/$\operatorname{Erode}$/$\operatorname{Interp}$/$\operatorname{diag}$，全文 $\Phi$ 出现 0 次、`\mathrm{Xxx}` 形式的算子 0 处。用 `\operatorname{}` 而非 `\mathrm{}` 是因为前者自带算子间距；`\mathrm{}` 仍用于非算子的直立体下标（$\mathrm{th}$/$\mathrm{db}$/$\mathrm{rnd}$/$\mathrm{lock}$/$\mathrm{ref}$ 等）与 $\mathrm{SE}(3)$。

**`\mathcal{}` 用量归零，不要回填**：$\mathcal{T}\to Q_o$（文本提示）、$\mathcal{M}\to G_o$（三维模型）、$\mathcal{K}_f\to K_f$、$\mathcal{B}_j\to B_j$、$\mathcal{H}_f\to H_f$。$G_o$ 与 $Q_o$ 同用对象下标 $o$ 成对，比字体区分更清楚，且掩膜 $M_f$ 与模型 $G_o$ 换字母后不再依赖「有无帧下标」来区分。**VRGA 实测 `\mathcal{}` 为 0 次**；其体系为黑正体给变换矩阵、普通斜体给标量与集合、`\mathbb{}` 只给空间、`\texttt{}` 给代码标识符，**且每个符号在首次出现处就地定义**。
