## 核心判断

你的新梳理比旧版 `design.md` 更准确。EgoAnchor 的核心技术确实可以归纳为三项：

1. **面向锚定的零样本感知流水线设计**
2. **逐观测 VCD 在线可靠性评分**
3. **运行时的观测校正与锚点合成**

但论文中不宜把它们表述成笼统的“前端和后端实现”。“实现”容易降低贡献层级，“前端/后端”也会与物理部署位置混淆。建议统一表述为：

> **感知后端的系统设计**与**对象锚定运行时的系统设计**。

整体论文则保持：

> **系统能力 → 感知后端设计 → 锚定运行时设计 → 系统评价**

你当前贡献列表只单独突出“系统”“VCD与运行时”“评价”，没有将感知流水线作为一项明确的系统设计；VCD和整个运行时又被压在同一个过长条目中，确实与最新思路不完全同步。

# 一、这三项技术应如何界定

## 1. 流水线设计可以作为贡献，但应定位为系统设计创新

当前四阶段流水线包含：

* 开放词表语义初始化；
* 时序对象分割；
* 双目米制深度；
* 模型驱动零样本6DoF注册与跟踪。

单独来看，这些组件大多来自既有方法，所以不能把贡献写成“提出了新的开放词表检测、分割或位姿算法”。真正的贡献是：

> 将这些能力组织成一套**面向动态锚定需求**的持续感知流水线，使其输出同时具有对象身份、米制尺度、采集时刻、帧标识、相机系位姿和可靠性信息。

因此建议将小节标题从：

> 零样本视觉流水线

改成：

> **面向锚定的零样本感知流水线**

这一改名不是包装，而是明确流水线为何这样组织。它的目标不是单帧识别，也不只是提高pose accuracy，而是生成锚定运行时可以持续消费的完整观测。

当前段落开头可以改成：

> 动态对象锚定要求感知后端在连续帧中同时维持目标身份、米制几何和六自由度位姿，并保留每个结果的采集时刻与可靠性。EgoAnchor据此将语义初始化、时序分割、立体几何重建和模型驱动位姿估计组织为四阶段流水线。四个阶段分别负责目标指定、身份保持、尺度恢复和位姿更新，最终生成式~\eqref{eq:observation}所定义的锚定观测。

这样，后面的四个阶段不再像四个现成模型的罗列，而是在回答一个统一的系统设计目标。

需要注意：你们目前没有对四阶段流水线逐项做消融。因此贡献措辞应使用：

* “设计并实现”
* “组织为”
* “生成满足锚定需求的观测”

不要写：

* “提出了优于现有方法的感知流水线”
* “证明了四阶段设计的最优性”

流水线的证据主要是完整系统运行、日常物体覆盖和候选输出性能；VCD与运行时机制才有更直接的组件消融。

## 2. VCD应称为“在线逐观测评分”，不建议以“即时”作为差异点

“VCD即时评分”可以表达运行时属性，但不适合用来区分你们与既有视觉论文。

MegaPose在推理过程中利用网络判断渲染假设与观测之间的匹配关系；FoundationPose也包含对精化候选预测分数并选择最佳位姿的pose-selection模块。因此，不能笼统声称此前的视觉评分都是离线的。([Proceedings of Machine Learning Research][1])

更准确的术语是：

> **逐观测在线VCD可靠性评分**

英文可用：

> **online per-observation VCD reliability scoring**

VCD与既有候选评分的真正区别不在“是否在线”，而在于**评分的系统角色**：

* 位姿估计器内部评分用于候选假设选择；
* VCD对最终输出候选进行显式、可解释的多模态验证；
* 评分被锚定运行时用于轨迹准入、失效判断和重新获取期间的有害更新抑制；
* 颜色或深度不可用时，评分能够按模态可用性退化。

建议小节标题改为：

> **逐观测VCD可靠性评分**

开头改为：

> 位姿估计器输出的最佳候选仍可能与当前图像观测不一致，而锚定运行时需要判断该候选是否足以更新持续存在的对象锚点。EgoAnchor因此为每个候选计算逐观测VCD可靠性评分。VCD将目标模型按候选位姿渲染回图像空间，并通过可视度、颜色和深度一致性度量候选与当前观测的支持程度。

这段直接说明VCD与内部pose score的不同用途，不需要防御性地强调既有方法不足。

另外，当前公式在 (\mathcal K_f=\varnothing) 时形式上仍有除零。正文虽然说明此时退化为 (R_f=V_f)，但应将公式前一句改成：

> 当 (\mathcal K_f\neq\varnothing) 时，VCD评分定义为对有效证据的加权几何平均：

公式后再写：

> 当两路证据均不可用时，多模态一致性项按实现取1，评分退化为纯可视度门控 (R_f=V_f)。

这样代码行为与数学定义都闭合。当前相关内容见手稿。

## 3. Runtime应明确拆为“观测校正”和“锚点合成”

这一划分成立，而且比旧版 `design.md` 中把时间对齐、VCD、滤波、StaticLock和生命周期平铺为多个模块更好。旧规划实际上也已经提出Observation Reconciliation与Anchor Synthesis，只是没有把感知流水线作为核心设计，也把VCD完全纳入了观测校正。

更准确的边界是：

### 感知后端

* 计算VCD评分 (R_f)。

### 运行时观测校正

* 消费 (R_f)；
* 恢复采集时刻的世界坐标语义；
* 检查时间单调性；
* 决定候选是否进入轨迹。

所以“观测校正”包括**VCD准入**，但不包括VCD评分的计算本身。

### 锚点合成

* 根据观测年龄确定查询时刻；
* 在接纳控制点间取值；
* 根据运动状态选择Tracking或Locked输出；
* StaticLock进入、保持和释放；
* 生命周期为锚点附加有效性与可信状态。

建议使用：

> **观测校正与准入**
> **运动状态感知的锚点合成**

“观测校正”单独使用可能让读者以为你们重新优化了候选位姿；加上“与准入”后，含义更明确。

# 二、贡献列表建议改为四条

我建议不要强行维持三条。你们现在具有两项边界清楚、且分别位于系统两层的技术设计：

* 感知后端：流水线 + VCD；
* 锚定运行时：观测校正 + 锚点合成。

EgoAnchor更适合四条：

```latex
\begin{enumerate}
  \item \textbf{EgoAnchor系统：}
  一套面向透视混合现实的零样本动态真实物体锚定系统。
  EgoAnchor通过分层的感知后端与锚定运行时，将异步、低频
  且质量波动的相机系位姿观测转化为稳定、世界一致且可恢复
  的世界系对象锚点。

  \item \textbf{面向锚定的零样本感知后端：}
  将开放词表语义初始化、时序对象分割、双目米制重建和模型
  驱动的6DoF注册与跟踪组织为持续感知流水线，并提出逐观测
  在线VCD可靠性评分，为运行时生成具有对象身份、采集时刻、
  米制位姿和显式可靠性的完整观测。

  \item \textbf{观测校正与运动状态感知的锚点合成：}

  StaticLock与生命周期管理，定义静止、运动、短时失效和

  \item \textbf{多层系统评价：}
  具有平台参考的受控基准量化完整系统的收益与响应代价；
  同候选流组件消融归因采集时刻对齐、VCD、StaticLock和
```

这四条的关系是：

| 贡献       | 回答的问题                         |
| ---------- | ---------------------------------- |
| 系统       | EgoAnchor整体实现了什么能力？      |
| 感知后端   | 如何生成适合锚定的零样本观测？     |

系统条目与技术条目存在一定包含关系是正常的。系统论文通常先声明完整能力，再展开最重要的系统设计。

## 3. (\mathcal H_c)是否规范

(\mathcal H_c)本身没有数学错误，但它只表示一个帧索引缓存，正文没有必要为缓存单独引入花体函数。并且 (\mathcal H) 在计算机视觉中容易让人联想到homography。

更简洁的写法是直接使用被检索出的相机位姿：

[
T_o^w(t_f)
==========

T_c^w(t_f),
\mathcal C!\left(T_o^{c_f}\right).
]

正文写：

> 运行时以帧标识 (f) 从历史缓存中检索采集时刻的相机世界位姿 (T_c^w(t_f))。

算法输入则直接写：

> 帧索引相机位姿历史

不必保留 (\mathcal H_c) 这一符号。

(\mathcal C(\cdot))则有保留价值，因为实际坐标约定转换是相似变换。建议补一句：

[
\mathcal C(T)=STS^{-1},
]

其中 (S) 是固定的轴向约定变换。无需单独编号。

## 5. 重写“查询时刻”

当前“运行时不查询当前时刻，而是……”正是你指出的AI式否定句，而且没有先说明为何需要历史查询。

建议改成：

> **查询时刻。** 最新控制点对应过去的图像采集时刻，其年龄还会随感知处理时间和候选间隔变化。运行时因此根据近期控制点年龄设置回溯量 (\Delta(t_r))，并在渲染时刻 (t_r) 查询
> [
> t_q=t_r-\Delta(t_r).
> ]
> 回溯量随近期观测年龄在线调整，并设有最小缓冲时长，使查询时刻通常能够由两个已经到达的控制点包围。

随后轨迹取值公式保持。

原来的长篇设计辩护可以压缩为：

> 该策略将观测时延显式保留在输出中，并避免对尚未观测的目标状态进行速度外推。实验二通过与Smoothed KF Extrapolation的对比量化其时延—残差权衡。

这不是防御性论述，而是说明设计选择和对应证据。无需在方法中进一步描述“过冲与回拉”。

## 6. StaticLock的表述

当前“死区内残差被判为噪声”“噪声与运动的判别边界”过于绝对，因为缓慢真实运动也可能暂时位于死区内。

建议改成：

> **锁内保持。** 锁定状态依据残差幅值采用不同更新路径。死区内的小残差按局部观测波动处理，并以受可靠性与头动调制的低增益缓慢吸收；死区外残差不直接写入锁定位姿，而进入运动证据累积。因此，死区构成锁内低增益更新与运动证据之间的分流边界。

CUSUM解释中的：

> 持续同向的偏移

应改成：

> 持续出现的死区外偏移

因为当前公式累积的是非负距离，并没有编码方向。

四类释放条件建议分点，但保持简洁：

```latex
系统在以下任一证据成立时请求退出锁定：
\begin{itemize}[nosep,leftmargin=1.2em]
  \item \textbf{持续残差：}带泄漏的累计证据超过门槛；
  \item \textbf{累计漂移：}观测共识相对入锁参考的平移或旋转偏移越界；
  \item \textbf{明确运动：}估计速度持续高于运动门槛；
  \item \textbf{可靠性下降：}候选可靠性持续低于释放要求。
\end{itemize}
```

随后单独总结：

> 前两类证据捕获空间偏移，后两类捕获持续时间和观测质量。释放在渲染帧边界提交，并通过短暂接缝过渡收敛至跟踪轨迹。

## 7. 生命周期存在一句实际矛盾

当前先写：

后面又写：

> 刷新新鲜度的门槛高于写入轨迹的准入门槛。

# 一、对Claude本轮裁定的判断

## 1. (\widehat) 的修改正确

删除“端到端时延”，改成由最新控制点年龄决定的回溯量，是必要修正。当前只用

[
t_q=t_r-\Delta(t_r)
]

定义查询时刻，再在文字中解释自适应回溯，语义已经清楚，也避免将观测年龄误写成capture-to-display latency。

这条不需要再改回去。

## 2. (\mathcal K_f=\varnothing) 时退化为 (R_f=V_f) 与代码一致

Claude在实现事实方面是对的。既然内部多模态聚合器在无有效模态时返回1，最终评分就应退化为纯可视度项，而不是零。

但当前公式形式上仍只适用于 (\mathcal K_f\neq\varnothing)，因为分母在空集时为零。后面的文字说明虽然能表达实现行为，数学域仍不够明确。

不需要增加分段公式，只需将公式前一句改为：

> 当 (\mathcal K_f\neq\varnothing) 时，VCD评分定义为对有效证据的加权几何平均：

公式后再写：

> 当 (\mathcal K_f=\varnothing) 时，多模态一致性项按实现取1，评分退化为纯可视度门控 (R_f=V_f)。

这样数学和代码同时闭合。

## 3. 保留算子 (\mathcal C(\cdot)) 是正确的

若坐标约定转换实际为

[
\mathcal C(T)=STS^{-1},
]

我上一轮建议写成单侧左乘矩阵确实不正确。Claude的否决成立。

不过当前只说它是“基变换”，读者还不知道它为何必须是算子。建议在不增加公式编号的情况下直接补充：

> 具体地，若 (S) 表示两坐标约定之间的固定轴向变换，则
> (\mathcal C(T)=STS^{-1})。

这会立即解释为什么不能简单左乘，也使 (\mathcal C) 不再显得是任意引入的符号。当前采集时刻对齐公式本身可以保留。

## 4. StaticLock保留独立子节是合理的

现在§3.3总起明确说明，第二步是在每个渲染帧合成连续位姿并在运动跟踪与静止锚定间选择输出；§3.3.2的输出公式也明确表示StaticLock是最终合成的一个分支。

因此，概念归属已经正确。StaticLock内容足够多，保留§3.3.3作为独立子节比强行塞入§3.3.2更利于阅读。

## 5. AURC不需要重新分析，但解释位置需要调整

这里我修正上一轮判断：**在你们的离散AURC定义下，Claude的解释成立。**

若一个event内候选顺序与误差无关，则在任一非零覆盖率下，所保留前缀的期望平均风险等于该event的总体平均风险；对覆盖率积分或取离散平均后，随机排序的期望AURC也等于全覆盖风险。因此，全覆盖风险可以作为“无判别排序”的期望AURC基线。

当前新增的1.46倍逐event配对倍率和12/12正向结果也足以说明排序一致性，不必重跑随机置换。

问题只在于，这个定义现在首次出现在**结果**中，读起来像事后解释。建议把原理移到§5.2评价指标：

> **VCD排序质量。** 对每个event，将候选按VCD评分降序排列，计算不同保留率下的平均位姿误差并取离散AURC。按该定义，若评分与误差无关，任一保留率下的期望风险均等于该event的全覆盖平均风险，故全覆盖风险构成无判别排序的期望AURC基线。AURC越低表示高分候选更集中于低误差区域。

结果部分则缩短为：

> VCD的AURC为……，全覆盖风险为……；全覆盖风险与AURC的逐event配对倍率为1.46……，12/12个event均显示正向排序收益。

这样更像预先定义的评价方法，不带防御感。

## 3. CUSUM解释中的“持续同向”与公式不一致

当前公式累积的是：

[
\max(0,d_{p,j}-d_{\mathrm{db}}),
]

其中 (d_{p,j}) 是非负距离，不含方向。它会累积持续的死区外残差，但不要求残差“同向”。当前文字写：

> “持续同向的偏移不断累积直至触顶。”

这在数学上不准确。改为：

> 孤立噪声尖峰在半衰期内被遗忘，而持续出现的死区外偏移不断累积直至触顶。

如果代码确实维护的是带方向的向量CUSUM，则应改变公式；根据当前标量距离公式，应该改文字。

## 4. “与头动强度成正比”过强

§3.3.1写道，错误锚点位移：

> “与头动强度成正比”。

严格来说，误差取决于采集与到达之间的相对相机变换、物体在相机坐标系中的位置以及旋转和平移分量，不是简单的标量正比关系。

建议改成：

> (t_f)至(t_a)之间的相机运动会被错误地写入对象的世界位姿，且该误差通常随采集后的头部运动增大而加剧。

这样仍然有明确物理含义，不会做过强数学承诺。

# 三、第3章剩余的语言精修

这些不需要改变机制，只需降低绝对化程度。

## 1. 查询时刻的“高概率”

当前写：

> “使 (t_q) ……以高概率落在已有控制点的覆盖区间内。”

正文没有概率模型或覆盖概率测量。“高概率”显得像未经证明的统计保证。

改成：

> 使 (t_q) 在观测间隔波动时通常仍落在已有控制点的覆盖区间内。

或者：

> 提高 (t_q) 落在已有控制点覆盖区间内的可能性。

## 2. 插值误差的表述

当前写：

> “以显式的历史滞后换取不随预测跨度放大的逐帧误差。”

这可能被理解为插值误差不受控制点间隔或运动加速度影响。更准确的是：

> 以显式的历史滞后避免引入随外推时距增长的预测误差。

完整句可改为：

> 插值输出始终位于已到达控制点之间，从而避免引入随外推时距和运动突变增长的预测误差，代价是显式的历史滞后。

## 3. 死区不是严格的“噪声—运动分类器”

当前称：

> “死区内残差被判为噪声”
> “死区是噪声与运动的判别边界”。

缓慢真实运动也可能暂时处于死区内，因此“判别”太绝对。建议改成：

> 死区内的小残差按局部观测波动处理，以低增益缓慢吸收；死区外残差不直接写入锁定位姿，而进入运动证据累积。死区由此成为锁内更新与运动证据之间的分流边界。

这比“噪声与运动判别边界”更符合实际机制。

## 4. 头动调制不能保证“吸收而不误判”

当前写：

> “使头动引起的观测滑移被吸收而非误判为物体运动。”

建议改为：

> 降低头动引起的观测滑移被误判为物体运动的风险。
