# 二、当前稿件为什么显得工程化

## 1. 方法主线被“执行步骤”取代

当前§3.3大量使用以下表述：

* 候选到达；
* 写入轨迹；
* 追加控制点；
* 刷新新鲜度；

* 缓存末端；
* 请求入锁或解锁；
* 模式转换；
* 状态计时。

这些内容未必错误，但它们回答的是：

> 代码何时执行什么操作？

学术方法应该优先回答：

> 系统状态如何定义？为什么需要这种设计？输入观测如何映射为输出锚点？该设计解决什么误差或权衡？

当前贡献第二、第三条分别列出流水线、VCD、对齐、准入、轨迹、StaticLock和生命周期。

正文总起又重复同样的模块。

结论再次完整列出全部机制。

结果是读者反复看到组件名称，却没有更清晰地理解三个核心技术问题：

1. 如何形成适用于锚定的零样本观测；
2. 如何判断观测是否可信；
3. 如何从异步观测生成逐帧锚点。

## 3. `design.md`过度固化实现细节

当前规划不仅规定核心贡献，还固定：

* 子节标题中的每个限定词；
* 生命周期代码状态；
* StaticLock的五类操作；
* 具体状态语义；
* 标题中哪些词必须出现。

这类信息应该位于代码事实或实现规范中。写作规划只需要规定论文主张、章节逻辑和证据边界，否则作者会不断围绕内部模块写作，而不是围绕研究问题写作。

# 十三、3.3.2锚点合成整体重写

这一节应成为运行时方法的中心，而不是控制点、回调和状态机的说明。

## 首段

```latex
\subsubsection{锚点合成}

给定接纳观测形成的世界系轨迹，锚点合成在每个渲染时刻
$t_r$生成最终对象位姿$\widetilde T_o^w(t_r)$。EgoAnchor首先
从轨迹中取得连续的跟踪位姿，再根据估计运动状态决定是否
保持稳定的静止锚点。
```

## 时间取值

```latex
\textbf{时间取值。}
异步观测对应历史采集时刻，且相邻观测间隔随处理时间变化。
EgoAnchor在渲染时刻查询
\[
t_q=t_r-\Delta(t_r),
\]
其中$\Delta(t_r)$依据近期观测年龄自适应调整，使$t_q$通常位于
两个已到达观测之间。
```

然后保留插值公式：

[
\widehat_o^w(t_q)
=================

\operatorname{Interp}
\left(
\widehat T_j,\widehat T_{j+1};
\frac{t_q-t_j}{t_{j+1}-t_j}
\right).
]

解释压缩为：

> 位置采用线性插值，旋转采用SLERP；边界外保持最近观测。该策略产生显式历史滞后，同时避免对尚未观测的目标状态进行外推。

不再写“轨迹末端控制点”“覆盖区间”“高概率”“预测误差随跨度放大”等长篇辩护。

## 静止锚定

将StaticLock完全并入该节：

```latex
\textbf{静止锚定。}
时间插值仍保留观测噪声所产生的静止波动。EgoAnchor因此根据
运动状态在跟踪与锁定两种输出之间切换：
```

保留最终输出公式：

[
\widetilde T_o^w(t_r)=
\begin{cases}
T_{\mathrm{lock}}^w,&m(t_r)=\mathsf{Locked},
\widehat T_o^w(t_q),&m(t_r)=\mathsf{Tracking}.
\end{cases}
]

然后把StaticLock压缩为三段。

### 进入

> 当平移和旋转运动在一段时间内保持低于静止门槛，且观测可靠性充分时，系统以当前跟踪位姿初始化 (T_{\mathrm{lock}}^w)。

### 保持

> 锁定状态以死区区分低增益位置修正与运动证据：死区内残差缓慢更新锁定位姿，死区外残差不直接改变输出，而进入带泄漏的累计证据。

保留CUSUM公式即可。

### 释放

不要保留四项itemize。改成：

> 锁定由持续死区外残差、相对入锁参考的累计漂移、持续运动速度或长期可靠性下降释放。这些证据分别覆盖快速运动、缓慢位移和观测退化；输出在释放后平滑收敛至跟踪轨迹。

这比四项列表更学术，也更紧凑。
