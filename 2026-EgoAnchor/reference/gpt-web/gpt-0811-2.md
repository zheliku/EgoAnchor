# 我建议第7章只保留两个subsection

```latex
\section{讨论}

\subsection{技术启示}

\subsection{局限与未来工作}
```

不要再增加很多7.1.1之类的层级。Discussion应该是一段完整论述，不应该像Methods一样碎。

下面是我建议的**可直接替换版本**。

```latex
\section{讨论}\label{sec:discussion}

\subsection{技术启示}

EgoAnchor展示了一条将现代视觉智能转化为混合现实系统能力的路径。
开放词表检测、视频分割、立体几何和零样本位姿估计正在显著扩展视觉系统
能够感知的真实对象范围，但这些模型输出的仍是带有采集时刻、相机坐标系、
不确定性和异步时延的视觉观测。对于混合现实应用而言，对象锚点还必须在
用户运动、物体运动、短时遮挡和观测间隙中持续提供世界一致的空间参考。
因此，视觉模型能够恢复物体位姿，并不意味着该位姿已经成为可供应用使用的
VR空间能力。

EgoAnchor在感知后端与锚定运行时之间显式处理这一差距。感知后端利用
视觉基础模型扩大对象感知的范围，并以逐观测VCD评分保留当前图像证据对
候选质量的约束；锚定运行时进一步恢复观测的采集时刻世界语义，并通过
观测准入、时间索引轨迹取值和静止锚定，把低频且质量波动的视觉结果转换为
逐渲染帧对象锚点。实验二表明，这些运行时处理并非位姿估计之后的附属平滑：
采集时刻对齐直接决定观察者运动是否被写入对象世界位姿，VCD限制低质量
候选进入轨迹，而静止锚定与轨迹输出策略进一步决定锚点在稳定性、轨迹
保真度与响应速度之间的行为。由此，AI感知与VR运行时承担的是互补职责：
前者提供开放对象上的视觉观测，后者定义这些观测如何进入持续的空间交互。

这一结果也说明，动态对象锚定不存在脱离应用任务的单一最优输出策略。
EgoAnchor在静止稳定、遮挡恢复和时延对齐后的轨迹保真度上获得更低误差，
代价是更长的起动响应以及持续平移时较高的当前时刻误差。用户研究进一步
显示，参与者在静止稳定、恢复一致、位置正确、依赖意愿与稳定--响应平衡上
更偏向EgoAnchor，而持续运动阶段的运动附着与姿态一致未检测到方法差异。
对于以放置后读取、对象说明和近物交互为主的混合现实应用，稳定的对象级
空间关系可能比最小化瞬时运动滞后更重要；对于快速连续操纵，则需要更偏向
实时响应的轨迹策略。对象锚定运行时因此应围绕应用如何消费锚点来选择
稳定性与响应性的工作点，而不能仅以单帧位姿误差作为优化目标。
```

这一版的核心变化是：

> 不再讨论“我们的指标为什么这样算”。

而是讨论：

> **AI/CV capability → uncertain visual observation → VR runtime → usable spatial capability**

这就是整篇论文可以升华的地方。

# 7.2我建议重点写你说的平台比较问题

这个问题值得正式讨论，而且我认为它应该成为局限性中**最重要的一段之一**。

但措辞不能写成：

> “我们无法和Vision Pro比较，所以没有比较。”

这会显得防御。

真正的问题是**跨平台6DoF对象锚点评价缺少共同参考系**。这是一个方法学问题。

可以这样写：

```latex
\subsection{局限与未来工作}

\textbf{对象与三维模型。}
EgoAnchor目前面向具有可用三维模型的刚性物体，其性能仍受目标的视觉
可观测性与模型质量约束。严重遮挡、极弱纹理、透明或镜面材质以及双目
深度失效都会削弱分割、几何恢复和位姿验证；非刚性对象则超出了本文的刚体
位姿模型。三维模型本身也参与位姿估计与VCD验证，因此模型尺度、几何形状
和对象坐标系中的误差会进一步传递至最终锚点。生成式Image-to-3D方法可以
降低新对象的模型准备成本，但其几何精度、尺度一致性与对象坐标系稳定性
将直接影响后续锚定质量。未来可进一步研究面向锚定的三维生成与模型校准，
并显式估计模型不确定性对位姿和锚点误差的影响。

\textbf{跨平台比较与评价参考。}
本文没有把不同商业平台的原生对象追踪直接作为数值基线。跨平台6DoF比较
首先需要一个独立于各运行时的共同对象参考：不同系统输出的对象位姿可能
采用不同的对象局部坐标系、模型原点与内部空间变换，如果缺少到统一对象
坐标系的标定关系，即使两套系统都输出六自由度位姿，其平移和旋转误差也
不能直接比较。将输出投影到二维图像后比较轮廓或关键点可以绕开部分坐标系
问题，但二维投影会弱化深度和绕视线方向的旋转误差，并受到相机投影、遮挡
和视角变化影响，因此不足以替代对象级6DoF锚点评价。

本文的受控实验选择Quest Touch Plus作为目标，是因为控制器的平台追踪位姿
与头显位姿位于同一平台世界坐标系，且目标几何与追踪原点之间可以建立固定
对应，从而为视觉锚点提供同步的平台参考。该设置使采集时刻对齐、静态与
动态误差以及转换响应能够在统一参考下比较，但它仍是平台参考而非独立的
物理真值，也不能据此推断EgoAnchor相对于其他商业平台追踪器的绝对优劣。
未来的跨平台评价可以引入外部光学动作捕捉或机器人运动平台，同时标定每个
系统的对象局部坐标系到统一参考系的刚体变换，从而在相同真实轨迹上比较
不同对象锚定系统。

\textbf{部署与评价基准。}
当前实现依赖外部GPU工作站，感知处理与通信产生的时延仍限制快速运动场景
中的当前时刻配准质量。随着视觉模型和推理硬件继续发展，进一步降低感知
延迟、提高候选频率以及向头显侧部署将扩大动态锚定的适用范围。与此同时，
本文的评价也表明对象锚定不能仅由单一平均位姿误差概括：静态保真度、动态
保真度和转换响应分别对应观察者运动、对象运动及观测中断和状态转换下的不
同行为。未来值得建立跨设备、跨对象的统一评价协议，在共享对象坐标系和
外部6DoF参考下，同时报告静止抖动、世界一致性、动态轨迹误差、有效时延、
遮挡恢复与起停响应，从而形成可复现的动态对象锚定基准。
```

我认为这里最后一段尤其有价值。

因为它把你们自己的三类评价：

[
\text{静态保真度}
\quad
\text{动态保真度}
\quad
\text{转换响应}
]

从“为了这篇论文设计的一套指标”进一步升成：

> **未来动态对象锚定评价可以考虑的一种系统级组织方式。**

这会让Evaluation本身也产生一点方法论价值，但又不会宣称“我们提出了新benchmark”。
