## 1. Discussion确实有一点“升得过高”

Claude当前开头：

> “EgoAnchor展示了一条将现代视觉智能转化为混合现实系统能力的路径……”

随后又使用“AI感知”“VR空间能力”等措辞。

想表达CV/AI与VR系统结合本身没有问题，但这句话已经比论文实际证据高了半层。EgoAnchor证明得最扎实的是：

> **零样本视觉位姿要成为可用的MR对象锚点，还必须经过运行时对时间语义、可靠性和持续输出行为的处理。**

所以我保留了“CV × VR”的主旨，但降成更具体的系统结论：

> EgoAnchor的结果表明，将零样本视觉感知用于混合现实对象锚定时，系统问题并不止于提高单帧位姿精度。……要形成可供应用持续绑定虚拟内容的动态对象锚点，运行时还需要恢复观测的时间语义、控制低质量观测进入状态估计，并在低频观测之间定义连续的逐帧输出。

后面再自然落到：

> 视觉感知负责扩大系统能够定位的对象范围；MR运行时负责决定这些观测如何成为可持续使用的对象级空间状态。

我认为这个层次更接近VRGA。VRGA的Discussion也确实会把技术结果提升到VR系统价值，但它仍然紧贴自身的Frontend/Backend、交互性和用户结果，而没有进一步抽象成一个很大的AI命题。

# 3. “静态保真度 / 动态保真度”我建议也换掉

这是这轮我认为最值得冻结的一个术语决定。

**两个都叫“保真度”确实不够准确。**

因为“动态保真度”下面不仅有：

[
\mathrm{LA\text{-}RMSE}
]

这种真正可以理解为trajectory fidelity的量，还有：

[
\text{effective lag}
]

和

[
\text{CT-RMSE},
]

它们描述的是响应时序和当前时刻误差，不完全是“fidelity”。

“静态保真度”同样混合了：

* head-motion leakage；
* absolute registration error；
* static jitter。

本质上是在评价**静止目标下的虚实配准行为**。

### 我最终推荐

[
\boxed{\text{静态配准}}
]

[
\boxed{\text{动态跟随}}
]

[
\boxed{\text{转换响应}}
]

这三个词我认为明显更合适。

### 静态配准

包含：

* 头动泄漏；
* 绝对配准误差；
* 静止抖动。

它回答：

> 目标不动时，锚点能否保持正确而稳定的虚实空间关系？

### 动态跟随

包含：

* effective lag；
* LA-RMSE；
* CT-RMSE；
* residual jitter。

它回答：

> 目标持续运动时，锚点如何跟随真实运动？

### 转换响应

包含：

* 遮挡恢复；
* start-transition。

它回答：

> 观测状态或运动状态发生变化时，锚点怎样转换？

所以逻辑变成：

```text
静止目标       → 静态配准
持续运动目标   → 动态跟随
状态发生转换   → 转换响应
```

这比：

```text
静态保真度
动态保真度
转换响应
```

语义层次更平行。

我已经把第5、6、7、8章，以及表2/3/4的caption全部按这三个名称统一。

## 4. “绝对注册误差”也顺手统一成“绝对配准误差”

这里需要区分两种`registration`。

FoundationPose内部的：

> 注册 / 追踪

是算法工作模式，所以：

```latex
\operatorname{Reg}
```

和“注册”仍然保留。

但是AR/MR里虚实空间之间的registration error，中文通常写：

> **配准误差**

更加自然。

所以评价指标统一成：

> **绝对配准误差**

这样也和新的“静态配准”形成一致的术语体系。

# 10. 你特别强调的“为什么不和Vision Pro / Quest直接比较”，现在这段逻辑是成立的

而且我建议保留，它是很有价值的一段Discussion。

我稍微改了叙述顺序，不再以：

> “本文没有比较……”

开头。

而先提出领域方法问题：

> **跨平台6DoF对象锚定尚缺少可直接共享的评价参考。**

随后解释原因：

[
T_{o,A}^{w_A}
\qquad\text{vs.}\qquad
T_{o,B}^{w_B}
]

本身并不可直接比较，因为：

* 对象局部坐标系可能不同；
* 模型原点不同；
* 世界系不同；
* 运行时可能还有内部coordinate correction。

要真正比较，至少需要：

[
T_{o,A}^{g},\quad T_{o,B}^{g}
]

都被标定到共同ground-truth frame (g)。

否则：

> 20 mm误差

甚至不知道是不是来自tracking，还是来自object origin定义不同。

而单纯投影到2D：

[
\pi(T_o^w)
]

又会丢掉深度和部分旋转信息，所以不能替代完整6DoF比较。

这个论证我认为很扎实，不是“找理由没做baseline”。
