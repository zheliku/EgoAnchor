## 1. 必须修：式 `lock-update` 当前在数学排版上其实是三分支

现在写成：

```latex
\begin{cases}
\operatorname{Interp}(...), \\
\qquad \text{若}\ d_{p,j}\le ...,\ d_{\theta,j}\le...,\\
T_{o,\mathrm{lock},j-1}^{w},\qquad\text{否则}.
\end{cases}
```

从LaTeX数学语义上，这是cases里的**三行**，而不是“第一行表达式 + 第一行条件”。虽然视觉上可能看起来可以接受，但数学排版是不规范的。

应该正式写成两列两分支：

```latex
\begin{equation}
T_{o,\mathrm{lock},j}^{w}
=
\begin{cases}
\operatorname{Interp}
\!\left(
T_{o,\mathrm{lock},j-1}^{w},
T_{o,j}^{w};
g_j
\right),
&
\substack{
d_{p,j}\le d_{\mathrm{db}},\\
d_{\theta,j}\le \theta_{\mathrm{db}}
},
\\[3pt]
T_{o,\mathrm{lock},j-1}^{w},
&
\text{否则}.
\end{cases}
\label{eq:lock-update}
\end{equation}
```

如果双栏宽度允许，也可以不使用 `\substack`。关键是条件必须处于cases第二列。

这是一处真正应该在冻结前修掉的公式问题。

## 2. 必须修：锚定参考的解释目前逻辑仍然有一点错误

现在写：

> “之所以需要这一对独立量，是因为锁定位姿在残差越界后即被冻结，无法再充当漂移的量尺。”

这里的因果并不准确。

真正需要独立 reference 的原因恰恰是：

> **锁定位姿在死区内允许低增益 creep，因此它不是一个固定参考。**

如果锁定位姿真的始终冻结，它反而完全可以作为累计位移的参考。

因此建议把这一段最后部分整体改成：

> 运行时另维护一个不受死区约束、持续跟随接纳观测的低通观测共识，并在入锁时冻结其当前值作为锚定参考 (T_{o,\mathrm{ref}}^w)。后续累计漂移由当前观测共识相对该参考的偏移度量。锚定参考与锁定位姿相互独立，使锁内的低增益位姿调整不会吸收目标自入锁以来的缓慢真实运动。

这一版的三个角色非常清楚：

[
\boxed{
\text{观测共识：持续跟随}
}
]

[
\boxed{
T_{o,\mathrm{ref}}^w：入锁时冻结
}
]

[
\boxed{
T_{o,\mathrm{lock}}^w：决定渲染，可低增益调整
}
]

这是StaticLock里一个真正重要的设计点，应当写准确。

## 3. 必须修：§3.4又把“控制点年龄”叫成了“实测时延”

你们此前已经专门修过这个语义，但现在Outline第4步又写：

> “按实测时延确定查询时刻”。

而式(14)实际使用的是：

[
\ell_r=t_r-t_j,
]

即**最新接纳控制点在当前渲染时刻的年龄**。

它不是严格测得的：

* 感知处理时延；
* 网络时延；
* capture-to-render latency；
* 更不是capture-to-display latency。

所以第4步改成：

> 在每个渲染时刻根据近期控制点年龄确定查询时刻，并在已有控制点之间取值得到跟踪位姿；

或者更简洁：

> 在每个渲染时刻确定历史查询时刻，并在已有控制点之间取值得到跟踪位姿；

我更推荐第二版。因为具体如何确定已经由式(14)解释，Outline不需要再次定义。

# 4. 建议修：StaticLock释放后的总结分类不够准确

现在写：

> “前两类度量空间偏移，后两类度量时间持续性。”

不太准确。

四类证据实际是：

* CUSUM：持续残差；
* reference drift：累计空间漂移；
* (\sigma_j)：运动速率；
* reliability：观测质量。

第三、第四类并不只是“时间持续性”。

建议直接改成一句非常准确的话：

> 前两类基于位姿偏移，后两类分别补充运动速率与观测可靠性。

然后后面的实现细节还可以再压一层。

目前这一段：

> 运动类门槛随头动强度自适应放大……重锁抑制窗口……收益与代价……完整阈值……

已经开始接近Implementation/Appendix。

建议最终只保留：

> 释放后，锚点通过短暂接缝过渡回到跟踪轨迹；头动调制、重锁抑制及完整阈值见附录~\ref{sec:appendix}。

这样StaticLock收尾会干净很多。

最终其阅读结构就是：

[
\text{Entry}
\rightarrow
\text{Hold}
\rightarrow
\text{Release}.
]

非常符合你想要的VRGA节奏。

# 5. 建议修：采集时刻对齐之后的解释仍稍微偏“辩护”

现在式(12)后有一整段：

> (S^{-1}=S)……共轭形式……帧标识而非时间戳……不依赖时钟同步……只恢复……不外推……

这里前半部分是必要数学解释，后半部分开始明显变成长说明。

建议压成：

> 其中 (S) 表示视觉坐标约定（(y)向下）到渲染坐标约定（(y)向上）的固定基变换，且 (S^{-1}=S)。帧标识将候选与其采集时刻的相机世界位姿直接配对，因此式~\eqref{eq:capture-alignment}得到与图像采集时刻一致的世界系观测。

就够了。

删除：

> “不依赖两侧时钟的同步精度”

以及：

> “不把目标状态外推至到达时刻”。

这些都是真的，但不需要在这里预先反驳潜在误解。后面的锚点合成已经清楚定义了时间取值。
