## 1. 什么是“锚点合成”

我建议把“逐帧锚点合成”明确界定为：

> 给定已经接纳的世界系观测轨迹、当前运动状态以及渲染时刻 (t_r)，生成应用在该渲染帧实际消费的世界系锚点位姿。

在这个定义下，锚点合成至少包含三个环节：

1. 确定查询时刻 (t_q)；
2. 从时间索引轨迹中得到连续跟踪位姿；
3. 根据运动状态决定最终输出跟踪位姿、锁定位姿或二者之间的过渡结果。

因此：

[
\text{accepted observations}
\rightarrow
\text{tracking trajectory}
\rightarrow
\text{motion-aware output}
\rightarrow
\widetilde T_o^w(t_r).
]

StaticLock 显然位于第三步。

目前手稿把“逐帧输出”和“静止锚定”拆成两个平级小节，容易造成一种错误印象：

> 先完成逐帧输出，然后再额外执行静止锚定。

但从你们的最终输出方程看并不是这样。最终位姿本身就是：

[
\widetilde T_o^w(t_r)=
\begin{cases}
T_{o,\mathrm{lock}}^w, & m(t_r)=\mathsf{Locked},
\widehat T_o^w(t_q), & m(t_r)=\mathsf{Tracking}.
\end{cases}
]

也就是说，**轨迹取值只生成 Tracking 分支的候选输出，StaticLock 决定最终使用哪个分支。** 所以静止锚定不是合成后的附加滤波，而是合成函数内部的模式选择。

# 2. 更准确的概念层级

我认为全文应该形成下面的三级关系。

## 第一层：观测处理

回答：

> 哪些视觉候选能够进入锚点运行时，以及它们在世界坐标系中表示什么？

包含：

* 采集时刻配准；
* VCD 准入；
* 状态估计；
* 写入时间索引轨迹；
* 更新运动状态和 StaticLock 证据。

输出不是应用锚点，而是：

[
\left{
(t_i,\widehat T_o^w(t_i))
\right}
\quad+\quad
\text{runtime state}.
]

## 第二层：锚点合成

回答：

> 在每个渲染时刻，应用实际得到什么位姿？

包含：

* 历史查询时刻；
* Linear/SLERP 轨迹取值；
* Tracking/Locked 模式选择；
* 锁内微调；
* 入锁与解锁；
* 解锁后的接缝过渡。

输出是：

[
\widetilde T_o^w(t_r).
]

因此 StaticLock 属于这一层。

## 第三层：生命周期管理

回答：

> 当前输出是否仍然可信、是否应当保持、降级、隐藏或重新获取？

它不主要决定正常 Tracking/Locked 状态下的位姿数值，而是决定：

* 输出有效性；
* 不确定性；
* Holding/Lost 状态；
* 重新注册与恢复；
* 应用是否继续呈现附着内容。

所以生命周期最好与锚点合成分开。它处理的是**锚点的存在与可信状态**，StaticLock 处理的是**锚点位姿如何输出**。

# 4. 为什么这种结构比“两个更新通路”更适合论文

“两类事件”是事实，但不是论文的核心方法分解。

如果按代码执行方式组织论文，就会出现你现在遇到的问题：

* StaticLock 证据在候选到达时更新；
* StaticLock 位姿在渲染时输出；
* 入锁请求由一侧产生、另一侧提交；
* 生命周期计时由观测更新、状态表现由渲染输出。

于是任何完整机制都横跨两类事件，很难归入“观测通路”或“渲染通路”。这正说明“两个通路”只适合作为 Algorithmic Outline 的调度说明，不适合作为方法章节的主要分类。

按功能组织后则非常自然：

[
\boxed{\text{观测处理}}
\rightarrow
\boxed{\text{锚点合成}}
\rightarrow
\boxed{\text{生命周期管理}}
]

其中：

* 观测处理建立可信的世界系轨迹；
* 锚点合成生成逐帧位姿；
* 生命周期决定该位姿当前以何种可信状态交付应用。

代码中它们可以异步交错，论文中不需要因此打乱概念层级。

# 5. “静止锚定”在锚点合成中的精确位置

还可以进一步区分：

## 轨迹合成不是完整的锚点合成

Linear/SLERP 得到的是：

[
\widehat T_o^w(t_q),
]

它只是一个连续的**跟踪轨迹位姿**。

它尚未考虑：

* 物体是否已静止；
* 是否应保持锁定位姿；
* 是否正在解锁过渡；
* 当前生命周期是否允许正常交付。

真正的锚点输出是：

[
\widetilde T_o^w(t_r)
=====================

\mathcal S!\left(
\widehat T_o^w(t_q),
T_{o,\mathrm{lock}}^w,
m(t_r)
\right),
]

其中 (\mathcal S) 表示运动状态感知的输出策略。

因此可以建立很清楚的术语层级：

* **轨迹取值 / trajectory sampling**：得到连续跟踪位姿；
* **锚点合成 / anchor synthesis**：结合 Tracking/Locked 状态得到最终位姿；
* **锚点交付 / anchor delivery**：结合生命周期提供位姿与可信度。

这一层级会让公式含义明显更清楚。

# 6. StaticLock的进入与解锁证据是否也属于锚点合成？

属于，但要区分“状态更新发生在哪里”和“机制属于什么”。

例如 CUSUM 是在新观测到达时计算的，但它存在的唯一目的，是决定未来的锚点输出模式。它不是观测质量验证，也不是轨迹估计本身。

所以在方法分类上，它属于 StaticLock／锚点合成；在 Algorithm 中，它列在“候选到达时更新证据”。

可以用一句话解决这种表面矛盾：

> 静止锚定是逐帧锚点合成中的运动状态感知输出策略。其运动证据随接纳观测更新，而模式转换和最终输出在渲染帧边界提交。

这句话已经准确表达了你们实现，不需要发明“跨轴状态”。

# 8. 生命周期是否也是锚点合成的一部分？

广义上可以说是，但论文中最好不要这样归类。

原因是生命周期主要改变的是：

[
(\widetilde T_o^w(t_r),,q(t_r)),
]

其中 (q(t_r)) 是锚点的有效性或可信状态。

StaticLock主要决定第一项——位姿；生命周期主要决定第二项——输出状态，并在 Holding/Lost 时约束第一项是否继续沿用。

因此最清楚的表达是：

> 逐帧锚点合成确定“输出在哪里”，生命周期管理确定“该输出当前是否以及如何被应用使用”。

两者都属于锚定运行时，但功能不同。

## 5. AURC不需要重新分析，但解释位置需要调整

这里我修正上一轮判断：**在你们的离散AURC定义下，Claude的解释成立。**

若一个event内候选顺序与误差无关，则在任一非零覆盖率下，所保留前缀的期望平均风险等于该event的总体平均风险；对覆盖率积分或取离散平均后，随机排序的期望AURC也等于全覆盖风险。因此，全覆盖风险可以作为“无判别排序”的期望AURC基线。

当前新增的1.46倍逐event配对倍率和12/12正向结果也足以说明排序一致性，不必重跑随机置换。

问题只在于，这个定义现在首次出现在**结果**中，读起来像事后解释。建议把原理移到§5.2评价指标：

> **VCD排序质量。** 对每个event，将候选按VCD评分降序排列，计算不同保留率下的平均位姿误差并取离散AURC。按该定义，若评分与误差无关，任一保留率下的期望风险均等于该event的全覆盖平均风险，故全覆盖风险构成无判别排序的期望AURC基线。AURC越低表示高分候选更集中于低误差区域。

结果部分则缩短为：

> VCD的AURC为……，全覆盖风险为……；全覆盖风险与AURC的逐event配对倍率为1.46……，12/12个event均显示正向排序收益。

这样更像预先定义的评价方法，不带防御感。

## 2. 插值误差的表述

当前写：

> “以显式的历史滞后换取不随预测跨度放大的逐帧误差。”

这可能被理解为插值误差不受控制点间隔或运动加速度影响。更准确的是：

> 以显式的历史滞后避免引入随外推时距增长的预测误差。

完整句可改为：

> 插值输出始终位于已到达控制点之间，从而避免引入随外推时距和运动突变增长的预测误差，代价是显式的历史滞后。

## 3. 死区不是严格的“噪声—运动分类器”

当前称：

> “死区内残差被判为噪声”
> “死区是噪声与运动的判别边界”。

缓慢真实运动也可能暂时处于死区内，因此“判别”太绝对。建议改成：

> 死区内的小残差按局部观测波动处理，以低增益缓慢吸收；死区外残差不直接写入锁定位姿，而进入运动证据累积。死区由此成为锁内更新与运动证据之间的分流边界。

这比“噪声与运动判别边界”更符合实际机制。

## 4. 头动调制不能保证“吸收而不误判”

当前写：

> “使头动引起的观测滑移被吸收而非误判为物体运动。”

建议改为：

> 降低头动引起的观测滑移被误判为物体运动的风险。
