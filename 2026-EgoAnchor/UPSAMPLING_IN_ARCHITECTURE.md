## 升采样的系统位置

升采样**不属于**四层协同架构本身，而是**第三层（时序平滑层）的输出功能**，作为从感知频率到渲染频率的桥梁。

## 升采样的工作原理

### 1. **基于状态估计的升采样**

不是简单的线性插值，而是利用卡尔曼滤波器的**预测步骤**：

```
观测到达 (t₀, 5-12 fps):
  卡尔曼更新: 状态 = [位置, 速度, 旋转]ᵀ

渲染帧间 (60 fps):
  卡尔曼预测: 
    位置(t) = 位置(t₀) + 速度 × Δt
    旋转(t) = 旋转(t₀) ⊕ 角速度 × Δt
```

### 2. **优势**

相比简单插值的优势：

- ✅ **有物理意义**：利用速度信息进行外推
- ✅ **平滑轨迹**：自然地连接观测帧间的运动
- ✅ **延迟补偿**：在观测到达前预测物体位置
- ✅ **噪声抑制**：预测步骤平滑了观测噪声

### 3. **与四层架构的关系**

| 层级               | 频率                            | 作用                   |
| ------------------ | ------------------------------- | ---------------------- |
| 第一层（时间对齐） | 5-12 fps                        | 消除头动打滑           |
| 第二层（质量门控） | 5-12 fps                        | 过滤异常观测           |
| 第三层（时序平滑） | 5-12 fps (更新) + 60 fps (预测) | 平滑 +**升采样** |
| 第四层（生命周期） | 事件驱动                        | 状态管理               |

**关键点**：升采样是第三层的**双重功能**：

- **观测更新**：以感知频率（5-12 fps）更新卡尔曼状态
- **预测输出**：以渲染频率（60 fps）输出预测锚点

## 为什么升采样重要

### 1. **用户体验**

- 低频锚点更新（5-12 fps）会导致视觉卡顿
- 60 fps 是头显渲染的基本要求
- 升采样填补观测帧之间的空白

### 2. **系统设计合理性**

- **感知端**：神经网络推理慢，5-12 fps 是现实约束
- **渲染端**：必须维持高帧率以避免眩晕
- **升采样**：用低开销的预测步骤弥补频率差距

### 3. **与其他系统的对比**

- **Vision Pro**：高帧率路径据报告也仅约 30 Hz
- **EgoAnchor**：通过卡尔曼预测升采样到 60 fps
- **优势**：更流畅的视觉体验

## 实现细节

### Unity 端实现逻辑

```csharp
// 每个渲染帧 (60 fps)
void Update() {
    float deltaTime = Time.deltaTime;
  
    // 检查是否有新的观测到达 (5-12 fps)
    if (HasNewObservation()) {
        // 卡尔曼更新步骤
        kalmanFilter.Update(newObservation);
    }
  
    // 卡尔曼预测步骤 (每帧都执行)
    Vector3 predictedPosition = kalmanFilter.PredictPosition(deltaTime);
    Quaternion predictedRotation = kalmanFilter.PredictRotation(deltaTime);
  
    // 输出 60 fps 锚点
    anchor.position = predictedPosition;
    anchor.rotation = predictedRotation;
}
```

### 静止锁定的影响

当物体处于静止锁定状态时：

- **观测更新**：仍以 5-12 fps 到达，但被锁定输出覆盖
- **预测输出**：直接输出锁定位姿，不进行预测
- **结果**：完全消除微抖，无论渲染频率

## 与审稿人的对话

### 可能的质疑

> "5-12 fps 的感知频率太低了，如何保证实时性？"

### 回应策略

1. **升采样机制**：通过卡尔曼预测升采样到 60 fps
2. **物理意义**：利用速度信息外推，而非简单插值
3. **实际效果**：评估表明视觉流畅性与平台级方案相当
4. **系统权衡**：在消费级硬件上这是感知质量与实时性的最优平衡

### 可能的质疑

> "预测会不会引入延迟？"

### 回应策略

1. **预测是前向的**：在观测到达前就已经外推
2. **与帧对齐配合**：时间对齐消除了主要延迟
3. **速度估计**：卡尔曼滤波器持续跟踪速度，预测准确
4. **实验验证**：时延评估（互相关分析）证明预测不增加感知延迟
