### GPT 方案的"糟粕"（要去掉的）

1. **`MotionStateClassifier` 保留是最大败笔。** GPT 自己在 Evidence 里写了 motion_state 翻转问题的边角，却仍保留离散 Static/Moving 双模式 + 静止锁定/释放阈值。我的数据证明这套**每秒翻转 1.56 次**正是静止晃动的隐患来源。One-Euro 用一个连续的 `cutoff = minCutoff + beta*|速度|` 同时解决静止稳和运动跟手，根本不需要离散态、不需要静止锁、不需要 release 阈值。GPT 的 config 里那 6 个 `static*` 参数全可以消掉。
2. **前推 0.15s 没有依据。** GPT 直接沿用旧值。我量化出实际未补偿延迟 ~156ms，前推策略应该是被论证过的决策（你已选"平衡 ~120-150ms"），不是抄旧值。
3. **Task10 的"验证"是假验证。** GPT 自己承认跑 eval 用的是旧数据，证明不了新算法效果。真正需要的是**用真机 aligned pose 回放喂进新 Tracker**做对照——这正是我方案的回归脚本要干的，但应该接到你现有的 eval 框架里输出 `anchor_error_summary`,而不是另起炉灶。
4. **`positionCorrection/velocityBlend` 这类参数仍偏多且耦合。** 它本质是手搓了一个简化 alpha-beta 滤波器,4 个融合比例参数互相影响,调参体验不会比现在好太多。One-Euro 的 `minCutoff/beta` 物理意义更清晰(截止频率 + 速度响应)。

## 3. 核心算法：AnchorTracker（One-Euro）

```csharp
// 每轴 One-Euro：cutoff 随速度自适应
//   dcutoff 固定；速度低 → cutoff≈minCutoff（强平滑，静止稳）
//                  速度高 → cutoff↑（弱平滑，跟手）
// alpha(cutoff, dt) = 1 / (1 + (1/(2π·cutoff)) / dt)
float Filter(float x, float dt) {
    float dx = (x - xPrev) / dt;
    dxHat += Alpha(dCutoff, dt) * (dx - dxHat);          // 平滑导数=速度
    float cutoff = minCutoff + beta * Mathf.Abs(dxHat);  // 自适应
    xHat += Alpha(cutoff, dt) * (x - xHat);
    return xHat;
}
```

要点：

* **位置 3 轴独立 One-Euro** ；**旋转**用四元数最短弧 + 角度 One-Euro（对 `Quaternion.Angle` 平滑，沿测地线 Slerp 推进）。
* **速度** `dxHat` 直接复用为前推速度，无需另设 KF。
* **异常剔除** ：测量与当前平滑态距离 > `maxJumpMeters` 或角差 > `maxJumpDegrees` → 丢弃该帧（计 Reject）。无马氏、无滞回、无多套恢复。这覆盖了实测 0.3% 的低分外点。
* **首测量/重定位** ：直接 Snap（`xHat=x, dxHat=0`）。
* **前推** `PredictAt(now)`：`pos = xHat + dxHat * min(now-tState, maxPredictAheadSeconds)`；旋转按角速度 Slerp 同样 clamp。
* **时间轴** ：沿用你现有的 captureTime 作为测量时刻、render time 作为输出时刻——这套异步对齐是对的，保留。
* **MotionState 显示映射** ：`|dxHat| < staticSpeedEps` 显示 Static 否则 Moving，仅写诊断字段，不影响任何分支（消除翻转副作用）。

## 4. AnchorLifecycle（4 态 + 重注册）

```
状态: Searching → Tracking → Coasting → Lost  (+ Paused/Error 外部命令入口保留)
转移:
  收到有效 pose            → Tracking, 刷新 lastPoseTime
  now-lastPoseTime>coast   → Coasting (Tracker 继续衰减前推)
  now-lastPoseTime>lost    → Lost (依配置; 默认不自动重连)
低分计时:
  score<lowScoreThreshold 连续累计 ≥ lowScoreReacquireSeconds
     且 距上次重注册 ≥ reacquireCooldownSeconds
     → 触发 OnNeedReacquire 回调; 重置计时器与冷却
```

`OnNeedReacquire` 是 `Action<string reason>`，由 PolicyController 暴露，Runtime 订阅后调 `AnchorCommandClient.ReacquireNextValidFrame()`。

## 5. AnchorPolicyConfig 新参数表（~12 个）

| 参数                         | 默认  | 作用                             |
| ---------------------------- | ----- | -------------------------------- |
| `positionMinCutoff`        | 1.0   | 静止平滑强度（越小越稳）         |
| `positionBeta`             | 0.5   | 速度→跟手响应（越大越跟手）     |
| `rotationMinCutoff`        | 1.0   | 旋转静止平滑                     |
| `rotationBeta`             | 0.5   | 旋转跟手响应                     |
| `derivativeCutoff`         | 1.0   | 速度估计平滑（One-Euro dcutoff） |
| `maxPredictAheadSeconds`   | 0.13  | 平衡前推上限（延迟补偿）         |
| `maxJumpMeters`            | 0.8   | 位置外点绝对门                   |
| `maxJumpDegrees`           | 90    | 旋转外点绝对门                   |
| `coastSeconds`             | 0.4   | 进 Coasting 阈                   |
| `lostSeconds`              | 2.0   | 进 Lost 阈                       |
| `lowScoreThreshold`        | 0.25  | 低分判定                         |
| `lowScoreReacquireSeconds` | 0.8   | 持续低分多久触发重注册           |
| `reacquireCooldownSeconds` | 3.0   | 重注册最短间隔                   |
| `enableLostAutoReacquire`  | false | （留开关）Lost 是否自动重连      |

`Validate()` 仅做下界 clamp，无 40 个互相耦合的约束。

## 6. 离线回归验证（交付前必做）

`tools/replay_policy_eval.py`：

1. 从 `20260613_012345` 的 unity_output 提取 `aligned_raw_*`（raw 输入）、时间戳、score、gt。
2. 用 Python 重现 One-Euro（与 C# 同公式）跑一遍。
3. 输出对比表：静止抖动(mm/帧)、运动误差 vs GT、等效延迟，三者对比  **新 One-Euro / 旧 kalman / raw** 。
4. **通过标准** ：静止抖动 ≤ 旧 kalman；运动误差 ≤ raw×1.0（即不再帮倒忙）；前推后等效延迟 < 旧 150ms 补偿后水平。
5. 不达标先调 `minCutoff/beta/predictAhead` 默认值，达标再写 C#。

> 这样保证"重构不退化"用你的真实数据背书，而非凭感觉，避免重蹈"效果不太好"。
