
# EgoAnchor 锚定方法实现计划

## 核心定位（一句话）

 **EgoAnchor 方法 = 任意 baseline 组合（motion model + smoothing strategy）+ Host 层内联的 anchor control（static-lock + score-gate）** 。baseline 就是开/关这两个 flag 的对照。论文创新在 anchor 层（静止锁定 + 信号敏感），不在滤波器本身。

主推：`Kalman + DelayedInterp(Hermite) + EgoAnchor(static-lock + score-gate)`。

---

## 为什么这样设计（你的诉求 → 机制映射）

| 你的诉求             | 机制                                                                     | 为什么是 EgoAnchor 独有                                                       |
| -------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 静止时一动不动       | Static Lock：motion-state==Static AND score高 AND 持续N帧 → 冻结整 pose | baseline（kalman/oneeuro/interp）信号无关，看不到 score，无法判定"可信的静止" |
| 运动时平滑跟上       | 解锁后交回 interp（你已验证满意）                                        | interp 天然过点、无 overshoot；EgoAnchor 只在静/动切换点加迟滞防抖            |
| 利用 pose score 优势 | score 进入 static-lock 判定 AND 低分时 Hold                              | 把 Python 的 7 子分 reliability 直接变成可见的 anchor 静止质量                |
| baseline 也是模块    | EgoAnchor 不是新 MotionModel/SmoothingStrategy 子类，是 host 的内联开关  | 同一 model+strategy 组合，开/关 flag = baseline vs EgoAnchor 消融             |

 **已确认决策** ：整 pose 锁 / 锁定+解锁双向迟滞 / 低分 Hold。

### A.6 新增 `UpdateStaticLock()` 方法（迟滞状态机）

![](./material-icons/csharp.svg)csharp

```
/// <summary>/// 静止锁迟滞决策：静止+高分连续 holdFrames 帧才锁；运动证据连续 unlockFrames 帧才解。/// 用 motionState（已由 UpdateMotionState 更新）+ score 双重证据。/// </summary>private void UpdateStaticLock(Pose candidatePose, float score){    if (!enableStaticLock)    {        latestStaticLocked = false;        staticLockCounter = 0;        staticUnlockCounter = 0;        return;    }
    // 静止证据 = 运动状态 Static AND 分数达标    bool staticEvidence = motionState == AnchorMotionState.Static                          && score >= staticLockMinScore                          && stateMachine.State == AnchorState.Tracking;
    if (latestStaticLocked)    {        // 已锁定：检测运动证据以解锁        if (staticEvidence)        {            staticUnlockCounter = 0;  // 仍是静止，清零解锁计数        }        else        {            staticUnlockCounter++;            if (staticUnlockCounter >= staticUnlockHoldFrames)            {                latestStaticLocked = false;                staticLockCounter = 0;            }        }    }    else    {        // 未锁定：积累静止证据以锁定        if (staticEvidence)        {            staticLockCounter++;            if (staticLockCounter >= staticLockHoldFrames)            {                latestStaticLocked = true;                lockedPose = candidatePose;  // 锁定在进入那一刻的输出 pose                staticUnlockCounter = 0;            }        }        else        {            staticLockCounter = 0;        }    }}
```

> **关键连续性保证** ：进入锁定时 `lockedPose = candidatePose`（当前帧 interp 输出），所以 C⁰ 连续无跳变；锁定期间恒等输出；解锁时下一帧 interp 输出会从锁定 pose 附近自然接续（因为 interp 的控制点在锁定期间仍被持续喂入——见 A.7）。

### A.7 关键：锁定期间继续喂运动模型（保证解锁后无缝）

锁定只冻结 **输出** ，不冻结 **状态更新** 。`AcceptPose` 里 `motionModel.UpdateState(observation)` 和 `smoothingStrategy.OnObservation(...)` 在锁定时 **照常执行** （现有代码 :230-234 不改）。这样：

* 锁定期间运动模型/控制点缓冲持续更新，速度估计保持新鲜；
* 解锁后 interp 的样条直接从最新控制点接续，不会因锁定产生数据空洞。

## B. Unity 离线仿真：`EgoAnchor_Tools3` 镜像实现

### B.1 新建 `Predictors/EgoAnchorPredictor.cs`（仿 ResidualBlendingPredictor，装饰器模式）

包一个底层 `IPredictor`（interp 或 blend），在其上加 static-lock + score-gate：

![](./material-icons/csharp.svg)csharp

```
public sealed class EgoAnchorPredictor : IPredictor{    private readonly IPredictor inner;  // 被装饰的 baseline（如 DelayedInterpolationPredictor）    private readonly double staticLockLinVel;   // m/s    private readonly double staticLockAngVel;   // rad/s（实测判定用）    private readonly double staticLockMinScore;    private readonly int staticLockHoldFrames;    private readonly int staticUnlockHoldFrames;    private readonly double scoreGateMinScore;  // 低分 Hold 阈值
    // 迟滞状态    private bool locked;    private Pose lockedPose;    private int lockCounter, unlockCounter;    private Vec3 lastLinVel, lastAngVel;  // 从最近控制点差分读取    private bool lastObservationGated;    // 上一帧是否被 score-gate 跳过
    public EgoAnchorPredictor(IPredictor inner, double scoreGateMinScore = 0.2,        double staticLockMinScore = 0.5, ...) { ... }
    public string Label => $"ego_{inner.Label}";
    public void OnObservation(in Observation observation)    {        // score-gate：低分时跳过 inner.OnObservation（Hold 语义：不更新，继续外推）        if (observation.Score < scoreGateMinScore)        {            lastObservationGated = true;            return;  // 不喂 inner，inner 用旧状态外推        }        lastObservationGated = false;        inner.OnObservation(observation);        // 读取最新速度（见 B.2）    }
    public Pose PredictAt(double renderTimeSeconds)    {        // static-lock 决策（迟滞）        UpdateStaticLock(...);        if (locked) return lockedPose;        return inner.PredictAt(renderTimeSeconds);    }}
```

### B.2 速度获取：从被装饰 predictor 的最近控制点差分（零侵入，不扩 IMotionModel）

由于 `inner` 可能是 interp（IControlPointSource 有速度）或 blend（IMotionModel 无速度），统一用差分：

![](./material-icons/csharp.svg)csharp

```
// 用 inner.PredictAt(t) 和 inner.PredictAt(t-ε) 差分估速度double eps = 1e-3;Pose at = inner.PredictAt(t);Pose prev = inner.PredictAt(t - eps);Vec3 linVel = (at.Position - prev.Position) / eps;Vec3 angVel = Quat.Log(prev.Rotation.Inverse() * Quat.AlignHemisphere(prev.Rotation, at.Rotation)) / eps;
```

> 与 `ControlPointSources.cs:48-51` 的差分样板完全一致，已验证可行。

## 风险与缓解

| 风险                                                         | 缓解                                                                                      |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| staticLockHoldFrames=5 在 12fps 输入下≈0.4s，可能让锁定太慢 | 参数可调；Inspector 暴露；离线仿真可快速扫参                                              |
| 整 pose 锁可能锁住物体被手微转的旋转                         | 你已确认接受；解锁迟滞 2 帧保证响应；后续可加"仅旋转更敏感"变体                           |
| 离线差分估速度有数值噪声                                     | eps=1e-3 与 ControlPointSources 一致，已验证；判定用阈值带余量                            |
| BadPoseInjector 接线后 baseline 也受影响                     | injector 只压 score，baseline 不消费 score 照单全收 = 正确对照；EgoAnchor 才用 score 拦截 |
