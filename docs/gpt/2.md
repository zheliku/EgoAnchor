当前代码也支持这个方向：[AnchorPolicyHost.cs (line 20)](P:/VSCode-Project/EgoAnchor/EgoAnchor_Unity/Assets/Scripts/EgoAnchor/Policy/AnchorPolicyHost.cs:20) 已经是 `MotionModel × SmoothingStrategy + gate`，baseline 可统一写成：

| 方法           | 模块组合                                                                  | 是否读 score |
| -------------- | ------------------------------------------------------------------------- | ------------ |
| raw/ZOH        | `cv + raw_passthrough + null_gate`                                      | 否           |

关键是： **baseline 全部不读 pose score** ，EgoAnchor full 才读 score、flags、lifecycle，并做静态锁定、坏观测抑制、coast/reacquire。这样实验就是比较“普通 temporal anchoring module”和“anchor-aware policy”，而不是滤波器排行榜。

我建议你的 EgoAnchor 方法这样实现：

1. **扩展 Unity 观测输入**
   现在 Unity policy 实际只用 `reliability_score` 和 flags；但 proto 已有 `score_phase / score_reprojection / score_depth / score_jump / score_mask / score_reject / score_confidence`。需要把这些字段从 `PoseResultPolicyMapper` 映射进 `AnchorObservation`，让 policy 能区分“没有几何证据”“遮挡”“真实快速运动”“坏跳变”。
2. **实现 Static Lock**
   当前 [AnchorPolicyHost.cs (line 149)](P:/VSCode-Project/EgoAnchor/EgoAnchor_Unity/Assets/Scripts/EgoAnchor/Policy/AnchorPolicyHost.cs:149) 的 `LatestStaticLocked` 固定 false，这正是缺口。静态锁定应当是 EgoAnchor 的核心：
   * 连续一段时间低速度、低角速度；
   * pose 相对短窗口 median/当前输出变化很小；
   * score 持续可信，`score_confidence` 高，`score_reject` 近 1；
   * mask/可见面积不过低；
     满足后进入 lock，输出固定 pose。此时新观测的小抖动不再推动物体显示。
3. **实现 Release / Moving**
   不能因为单帧 `score_jump` 低就认为坏 pose，因为真实快速运动也会降低 jump 分。释放静态锁应靠“持续运动证据”：
   * 高可靠观测连续偏离 locked pose 超过阈值；
   * 或 motion model 速度连续超过阈值；
   * 或多帧方向一致的位移/旋转趋势。
     低分、遮挡、无 pose 时不要释放锁，而是 hold/coast；否则遮挡会把静止物体“抖开”。
4. **动态阶段用你满意的 interp**
   你现在更满意 interp，这很合理。尤其 5090 Ubuntu 上 Python 输入约 12fps 后，观测周期变短，interp 的体感延迟压力会小很多。推荐先把 EgoAnchor full 做成：
   `KalmanModel + DelayedInterpStrategy + score-aware static lock`
   baseline 则保留 `kalman_interp + null_gate`，这样可以明确证明增益来自 anchor-aware 行为，不是来自 interp 本身。

论文实验可以这样组织：

* RQ1：`arrival_time_raw` vs `frame_aligned_raw`，证明 frame alignment 是 MR world consistency 的关键。
* RQ2：raw、blend、interp、Kalman、OneEuro、CV 都作为模块 baseline，比较 jitter/lag/slip。
* RQ3：最佳 baseline module + `null_gate` vs 同 module + EgoAnchor static lock/gate/recovery，重点看静态 jitter、坏 pose spike、遮挡/出视野恢复。

我的建议是走这个定位： **EgoAnchor = frame-aligned mapping + temporal anchoring modules + reliability-aware static lock/lifecycle** 。其中 baseline 是模块，EgoAnchor full 是同一框架上的 anchor-aware policy。这样既符合现有工程，也最能凸显“真实物体锚点属性”。
