可以这样抽象，但我会稍微改名：

`真实pose -> 预测 -> 滤波 -> 渲染`
更准确应是：

`观测 pose -> 接纳/校正 -> 状态预测 -> 输出滤波 -> 渲染应用`

原因是 runtime 里拿不到“真实 pose”，拿到的是 Python 返回的 `frame-aligned observation`。真实 pose 只应该出现在 eval/GT 里，不能进入 policy。

**推荐架构**

我建议做成“固定主流程 + 可替换模块”，不要做完全任意 graph。完全任意组合会很灵活，但论文实验容易变得不可解释。

```
PoseResult
  -> FrameAlignedObservation
  -> AnchorPolicyRunner
       -> IAnchorGate
       -> IAnchorTracker
       -> IAnchorOutputFilter
       -> IAnchorLifecycle
  -> AnchorPolicyOutput
  -> DynamicObjectAnchor
```

核心类型可以这样设计：

```
public sealed class AnchorPolicyRunner
{
    private IAnchorGate gate;
    private IAnchorTracker tracker;
    private IAnchorOutputFilter outputFilter;
    private IAnchorLifecycle lifecycle;

    public AnchorPolicyDecision Accept(AnchorObservation observation);
    public AnchorPolicyOutput Advance(double renderTimeSeconds);
    public void Reset(string reason);
}
```

模块接口：

```
public interface IAnchorGate
{
    AnchorGateDecision Evaluate(AnchorObservation obs, AnchorTrackerState state);
}

public interface IAnchorTracker
{
    bool HasState { get; }
    AnchorTrackerState State { get; }
    void Snap(Pose pose, double captureTime);
    void Correct(Pose pose, double captureTime, AnchorGateDecision gate);
    AnchorTrackerState Predict(double renderTime);
    void Reset();
}

public interface IAnchorOutputFilter
{
    AnchorPolicyOutput Advance(AnchorTrackerState target, AnchorLifecycleState lifecycle, double renderTime);
    void Reset();
}

public interface IAnchorLifecycle
{
    AnchorLifecycleState Update(AnchorGateDecision decision, double now);
    void NotifyMissing(double now, string reason);
    void Reset(string reason);
}
```

Unity Inspector 不建议直接序列化接口。更稳的是用一个 profile：

```
AnchorPolicyProfile ScriptableObject
  label = raw / kalman / oneeuro / kalman_oneeuro / full
  gateKind = Always / ScoreJump
  trackerKind = RawHold / Kalman / OneEuro / KalmanPredictOneEuro
  outputKind = Direct / RateLimited / StaticLock
  lifecycleKind = None / Basic / ScoreRecovery
```

`AnchorPolicyRunner` 根据 profile 创建 plain C# 模块。这样 baseline 可复现，也方便 eval 写入 `label`。

**Baseline Profile**

建议保留这些 profile：

| label              | gate      | tracker                               | output                 | 目的                |
| ------------------ | --------- | ------------------------------------- | ---------------------- | ------------------- |
| `raw`            | Always    | RawHold                               | Direct                 | 最弱 baseline       |
| `lowpass`        | Always    | RawHold                               | ExpLowPass             | 传统平滑            |
| `kalman`         | Always    | Kalman                                | Direct/RateLimited     | 经典状态估计        |
| `oneeuro`        | Always    | OneEuro                               | RateLimited            | 强交互滤波 baseline |
| `kalman_oneeuro` | Always    | KalmanPredict                         | OneEuroOutput          | 检验组合是否有收益  |
| `full`           | ScoreJump | KalmanPredict + score-adaptive output | StaticLock + RateLimit | 你的方法            |

**Kalman + One Euro 是否更好**

可能更好，但前提是职责不能重叠。

推荐顺序：

```
measurement at capture time
  -> score/jump gate
  -> Kalman update：估计位置、速度、旋转、角速度
  -> predict to render time：补偿低频和延迟
  -> One Euro output filter：只做显示层平滑
  -> static lock / rate limit
```

不要做：

```
One Euro 先滤 measurement -> Kalman
```

这会把坏 pose 和延迟揉进状态估计，速度估计也会被污染。

也不要简单：

```
Kalman 输出 -> One Euro 强滤波
```

这容易双重平滑，运动误差变大。你之前看到 Kalman 运动时可能比 raw 差，本质就是这种风险。

更合理的融合是：

1. Kalman 负责“状态”和“预测”：解决低频到 render-rate 的问题。
2. One Euro 负责“输出观感”：抑制 render pose 的小抖动。
3. pose score 进入两个位置：
   * gate：低分不更新或只 hold；
   * measurement noise / cutoff：分数低时 Kalman `R` 变大，One Euro cutoff 变低。

例如：

```
R_eff = R_base / clamp(score, floor, 1)^2
cutoff_eff = minCutoff + beta * speed * scoreWeight
```

我的判断：`Kalman prediction + score-adaptive One Euro output` 是值得做的 full-method 候选，但不能默认认为一定优于 vanilla One Euro。它应该作为一个明确 profile 和 ablation 跑出来。

**我建议的最终设计**

论文方法可以叫：

`Reliability-aware Render-rate Anchor Synchronization`

内部由三层组成：

1. **Observation Admission** ：score、flags、stale、jump gate。
2. **State Prediction** ：Kalman 或 One Euro tracker，把 capture-time pose 扩展到 render-time target。
3. **Display Stabilization** ：One Euro output、static lock、rate limit、hold/coast/lost lifecycle。

这样比“滤波器堆叠”更像论文贡献：你不是说“用了 Kalman 和 One Euro”，而是在解决“异步低频 object pose 如何同步成 MR render-rate anchor”。
