# RQ1 分析设计文档

## 研究问题

**RQ1: Anchoring Quality** — EgoAnchor 能否在开放消费级 PMR 场景中实现满足应用需求的动态对象锚定？具体在精度、稳定性、响应性和鲁棒性维度表现如何？

## 关键决策

### 1. 运动模式分类策略

**现有数据标签**：

- `static_observation` (4669 frames, 78s)
- `occlusion_recovery` (2238 frames, 38s)
- `slow_translation` (2195 frames, 38s)
- `rotation` (3009 frames, 50s)
- `fast_motion` (3197 frames, 54s)
- `unlabeled` (3338 frames) - 需要确认这是什么

**决策：保持5个主要场景，不合并快慢速运动**

**理由**：

1. **慢速 vs 快速的区分有科学价值**：

   - 慢速（5-10 cm/s）：日常操作场景（拿起、移动、放下）
   - 快速（50+ cm/s）：挑战性场景（挥动、快速传递）
   - 两者的误差来源不同：慢速主要受视觉追踪精度限制，快速则受时延影响
2. **旋转单独分析**：

   - 旋转场景的误差特征与平移不同（论文已指出：特征点像平面位移小）
   - 可以揭示系统在不同运动类型下的行为差异
3. **遮挡恢复单独分析**：

   - 测试鲁棒性维度，不是常规运动场景
   - 关注恢复时间和连续性，而非精度

**最终场景分组**：

- **静止观察**：测试稳定性（抖动、屏幕漂移）
- **慢速平移**：测试日常操作精度
- **快速挥动**：测试高速响应性和时延影响
- **旋转运动**：测试姿态估计精度
- **遮挡恢复**：测试鲁棒性（恢复时间）

### 2. 对齐方式选择

**核心问题**：运动场景下，anchor输出应该与哪个GT对比？

- **选项A**：与"当前帧"的GT对比（naive比较）
- **选项B**：与"时延补偿后"的GT对比（对齐后比较）

**决策：同时报告两种对比，但主结果使用选项B**

**理由**：

1. **选项A的价值**（报告但不作为主结果）：

   - 反映"用户实际感知的误差"
   - 包含时延导致的动态配准误差
   - 用于分析"时延对误差的贡献"
2. **选项B的价值**（作为主结果）：

   - 隔离视觉追踪算法的真实精度
   - 公平评估：不惩罚系统设计已经补偿的时延
   - 符合论文核心主张："关键在于把异步感知放在正确的时间轴上"

**实现方式**：

```python
# 方法1：当前帧GT（反映用户感知误差）
error_naive = compute_error(anchor_pose_at_t, gt_pose_at_t)

# 方法2：时延补偿GT（隔离追踪精度）
# 根据端到端时延，回溯GT到采集时刻
latency_ms = 111  # 中位数
gt_pose_aligned = interpolate_gt(t - latency_ms)
error_aligned = compute_error(anchor_pose_at_t, gt_pose_aligned)

# 报告：
# - 主结果：error_aligned（Table + 核心图表）
# - 时延影响分析：error_naive - error_aligned（专门的子图）
```

**在论文中的呈现**：

- **主表格/图表**：报告`error_aligned`（标注为"时延补偿后误差"）
- **时延影响分析**（单独子图）：
  - 展示`error_naive vs error_aligned`的对比
  - 散点图：误差 vs 物体速度（验证线性关系）
  - 量化时延贡献：`error_naive - error_aligned` 占总误差的百分比

### 3. 评估指标体系

**按维度分组**：

#### **A. 精度（Accuracy）**

- **平移误差**：RMSE, Median, P95（单位：mm）
- **旋转误差**：RMSE, Median, P95（单位：度）
- **报告策略**：
  - 静止/遮挡恢复：报告绝对精度
  - 运动场景：报告时延补偿后的精度

#### **B. 稳定性（Stability）**

- **静止期抖动**：位置RMS, 旋转RMS（高通滤波后）
- **屏幕空间漂移**：像素级漂移（投影到像平面）
- **报告策略**：
  - 主要在静止场景报告
  - 运动场景的"抖动"反映的是追踪残差，不是真正的稳定性问题

#### **C. 响应性（Responsiveness）**

- **端到端时延**：采集→渲染（P50, P90, P95）
- **时延分解**：感知各阶段耗时（YOLO, Depth, Cutie, Pose, 传输）
- **运动滞后**：速度互相关峰值位置（ms）
- **报告策略**：
  - 时延：全场景统一报告（应该高度一致）
  - 滞后：仅在运动场景报告

#### **D. 鲁棒性（Robustness）**

- **恢复时间**：短暂丢失后重新锚定的时间
- **追踪连续性**：Lost状态占比
- **报告策略**：
  - 主要在遮挡恢复场景报告

- 分颜色标记不同场景
- **关键信息**：误差与速度线性相关，验证时延补偿的有效性

### 6. 数据处理流程

#### **输入数据**

- `unity_output.jsonl`：逐帧GT和anchor输出
- `python_runtime.jsonl`：感知后端日志（可靠性评分、时延等）

#### **处理步骤**

1. **数据清洗**：

   - 过滤`anchor_state != "Tracking"`的帧
   - 过滤`gt_pose_valid != true`的帧
   - 过滤`unlabeled`条件（需要确认这是什么）
2. **GT时延对齐**：

   - 对每一帧anchor输出，根据`capture_to_apply_ms`回溯GT
   - 使用三次样条插值重建历史GT位姿
3. **误差计算**：

   - 平移误差：欧氏距离
   - 旋转误差：四元数角距离
4. **抖动计算**：

   - 高通滤波（cutoff=1Hz）提取高频分量
   - 计算RMS
5. **屏幕空间漂移**：

   - 使用相机内参投影到像平面
   - 计算像素级距离
6. **滞后计算**：

   - anchor速度与GT速度的互相关
   - 峰值位置即为滞后

#### **输出**

- `rq1_results_summary.csv`：按场景汇总的统计表
- `rq1_results_detail.csv`：逐帧详细数据（用于绘图）
- `fig_rq1_comprehensive.pdf/png`：主图
